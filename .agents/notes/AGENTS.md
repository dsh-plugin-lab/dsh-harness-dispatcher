# .agents/notes/ — 规则层

继承根规则，见 [../../AGENTS.md](../../AGENTS.md)。本文件只写「往这里写记录要遵守什么」；
目录结构与命名见 [README.md](README.md)。

## 每篇第 3 行必须是状态行

四值之一，且必须落在第 3 行（前面只有一级标题和空行）：

```
状态：生效
状态：被取代      ← 必须紧跟一行指针，指向取代它的那篇
状态：已否决      ← 必须紧跟一句话理由
状态：已归档      ← 必须紧跟一句话理由
```

**归档就地标记，不建 `archived/`。** 失效的记录留在原位置 —— 移动会打断所有指向它的链接，
而记录的价值恰恰在「还能被找到」。

## 两类的结构不一样

| | 决策类 | 依据类 |
|---|---|---|
| 触发源 | 做选择（在几个方案里挑一个） | 做调查（看事实、对照、得出结论） |
| 必须有的节 | `## 问题` / `## 决策` / `## 替代方案（强制）` / `## 影响` | `## 背景` / `## 结论` / `## 影响` |
| 替代方案 | **强制**：不记录被打败的选项，下次必被重诉 | 可选（依据本身没有选项） |
| 指向下游 | `## 影响` 里写代价与收益 | `## 支撑的决策` 指回决策类 |
| 命名 | `YYYY-MM-DD-<主题>` | 沿用原名（依据是「一段时期的调查」，不是某天的选择） |

## 描述已落地的事实用现在时

**不写「改成 / 新增了」**，直接写「它是什么」。事实变化（路径、默认值、机制名）**就地更新**，
不新开一篇 —— 否则同一个机制会有五篇各说各话的记录。

**只有决策反转才写新记录**，并交叉引用旧的。

## 不许 retcon（追改历史）

历史记录的过期内容**不算债**。`2026-11-10-*` 里提到的 `src/harness.ts`（当时的形状）
就该保持原样 —— 它是当时的事实。**只有指错路的链接才修，过期的结论不改。**

## 别把事故写进这里

事故触发 → `docs/postmortem/`（**按需创建，目前尚未创建**）。
判据：**事故**（有代价、有影响面）→ postmortem；**决策或调查** → notes。
一次小失误不值得复盘，写进根 AGENTS 的「活跃坑」就够。

## 别把验收清单写进这里

`## 待办` / checkbox 式的进度表属于 `docs/PLAN.md` 或根 AGENTS 的待办节。
记录回答的是「为什么这么定」，不是「还差什么没做」。
